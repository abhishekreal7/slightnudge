Editor Build Sprint 1: engine gap closeouts, overlay polish, and controls wave 1 on SlightNudge's own safe edit engine. Work in order; stop at a clean boundary.

CONTEXT
SlightNudge edits real React/Next + Tailwind code visually through inspect, preview, apply and undo (AST edits, refusals, token-level undo, project-scoped Tailwind v3/v4 verification, token/Host/Origin auth, atomic writes, helpers in test/helpers/test-server.ts). A spike (docs/editor/onlook-spike.md, if present) found: the engine is stronger than the open-source Onlook editor on safety, but the studio UI (app/studio/[repoId]/page.tsx, components/slightnudge/SlightNudgeOverlay.tsx, importedStyleOptions) only exposes presets and omits controls the engine already allowlists (border width/color, font style, text decoration); new capabilities are needed (opacity, height, min/max, margin, per-side padding, per-corner radius, gap-x/y, shadow presets, z-index, object-fit, validated arbitrary values); the apply route compares file content to the reviewed "before" and THEN awaits Tailwind verification before writing (possible race window); undo refuses elements inside conditional ancestors while the style inspection path does not (asymmetry to characterize). Known UI problems: floating toolbar can cover the selected element; drag drop indicator is a thick glowing line with end dots and a jargon badge ("Drop here (Position 2 of 3)") overlapping the toolbar; two duplicate Apply buttons ("Apply to code" in the inspector and the floating "Apply to Source", same handler applySourceEdit, route POST /api/slightnudge/apply); stale session token after a server restart has no designed behavior; several studio browser suites fail (step1, step2, step3, move-expectations, studio-restore, drag-resize-move, studio-benchmark: outdated selectors and no test server).

PART 1: engine closeouts (small, test-first)
a. Compare-and-swap at write time: after all async checks (including Tailwind verification) and immediately before the atomic write, re-read the target and compare it to the reviewed "before" content; on any difference refuse with a plain message and leave the external change intact. Test with the guarded pre-write hook (SLIGHTNUDGE_TEST=1 and NODE_ENV not production): an external edit inserted between verification and write must survive, with nothing written and no temp file. Apply the same pattern to the undo write if it is missing there. Mutant check: removing the re-compare must fail a test.
b. Conditional-ancestor characterization: tests for an element inside a ternary, &&, if and inside a component used once. Required: an edit applied there can always be undone exactly (byte-identical) when the file is unchanged; when the file changed, undo either reverts only the token or refuses with manual instructions; never a wrong target or a stuck state. Change behavior only if a test exposes a wrong-target or stuck state; otherwise just document the result in the report and keep the tests.

PART 2: visible polish (contract, then tests)
a. docs/editor/overlay-contract.md and implementation. States: Idle, Hover, Selected, TextEditing, Dragging, Resizing, Previewing, Applying, Error. While Dragging or Resizing only the target outline and the drop indicator show. Drop indicator: thin 2 px accent-color line spanning the width of the parent container, no end dots, no glow, no badge or text; moving element ghosted at low opacity. Toolbar: hidden during drag, resize and scroll; placement prefers above the selected element, flips below when there is no room, clamps inside the viewport, never overlaps the selected element or the drop indicator. Every overlay disappears after drop, Esc, failed drop and blur. Playwright tests: geometric no-overlap assertions, a screenshot per state against baselines in test/visual-baselines/ (small PNGs, pixelmatch, documented tolerance, script to regenerate deliberately), and a stuck-overlay test for drop, cancel and failure.
b. One Apply: first prove in a test that both buttons share the same save path, then keep ONE floating Apply and remove the duplicate. Shortcuts: Ctrl/Cmd+Enter applies, Esc discards the preview, Ctrl/Cmd+Z undoes; add redo only if the history layer supports it without weakening any safety check, otherwise leave it as a written spec.
c. Error copy (docs/editor/copy.md, plain words for non-coders) and behavior: stale or missing token: the client refetches the token once and retries the request once, never loops, then shows "The editor lost its connection to your project. Reload the page."; file locked; "can't verify this class"; refusals; undo manual instructions; server restart clears the unapplied draft with a notice. Test the stale-token path with a real server restart in dev and production, and the refresh behavior (applied edits survive reload, unapplied preview is discarded with a notice).

PART 3: UI test infrastructure
a. Add stable data-testid attributes per docs/editor/testids.md. Find each failing studio suite's REAL failure reason first, then repair it through the temp-workspace helper with an app server on a free port. Table in the report: suite, reason, fix, before/after. Suites that cannot be repaired without weakening an assertion stay BLOCKED with the exact reason.
b. test/helpers/prove-control.ts: proveControl() = select the element, change the value through the UI only, assert the live preview with getComputedStyle, Apply, assert the source diff with an independent @babel/parser oracle (only the intended className tokens changed; elements carry test-injected data-fz ids; never ts-morph), reload and assert the same computed style, Undo and assert byte-identical source. proveRefusal() = unsafe selection shows a plain-language reason and writes nothing.

PART 4: controls wave 1 (per control: registry entry in docs/editor/registry.json with utilities written, conflict group, refusal conditions and proof link; failing test first; proveControl; keyboard operable with visible focus; axe-core with no serious violation on the panel; states default, hover, focus, disabled-with-reason, error, reset)
a. Expose controls the engine already allows but the UI omits: border width, border color, font style, text decoration; review the rest of the studio presets against the engine allowlist and list gaps.
b. New engine capabilities, each with a conflict group (replace or remove tokens of the same family and the same variant, keep unknown tokens, never reorder untouched tokens) and verification through the project's Tailwind engine: opacity; height, min/max width and height; margin; per-side padding and margin; per-corner radius; gap-x and gap-y; box-shadow presets; z-index; overflow; object-fit.
c. Arbitrary values (for example w-[37px]) only through a strict grammar: numbers with units px, rem, em, %, vh, vw; hex colors; nothing else. The generated token must match a strict regex, never contain whitespace, quotes, brackets inside the value, backslashes, underscores or JSX-breaking characters, and must keep the className literal valid. Reject everything else with a plain message. Add a fast-check fuzz test (record seeds) proving no accepted input can produce a token outside the grammar or break the literal.
d. UI: grouped panel sections consistent with the existing look; a NumberField (typed input, arrow steppers, Shift for x10, unit select, reset) and a SegmentedControl as small reusable components; refusal reasons shown in plain language near the control. Keep it original and consistent; no emoji.
e. Failure-injection test per capability group: file read-only, file locked, server killed mid-Apply, file changed between preview and apply: clear message and unchanged or consistent file.
