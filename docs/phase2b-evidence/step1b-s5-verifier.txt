--- ROOT CAUSE INVESTIGATION FOR bg-brand-500 REFUSAL ---
In lib/slightnudge/tailwind-verifier.ts:
L132: ds = await twNode.__unstable__loadDesignSystem('@import "tailwindcss";', { base: projectDir });
L145: const compiler = await compileFn('@import "tailwindcss";', { base: projectDir, ... });

In Tailwind v4, passing '@import "tailwindcss";' alone without '@config "./tailwind.config.js";' does NOT load legacy tailwind.config.js configurations.
Direct experiment (scratch/test-tw-config.cjs):
- Without @config: ds.candidatesToCss(['bg-brand-500']) => [ null ] (fails)
- With @config "./tailwind.config.js": ds.candidatesToCss(['bg-brand-500']) => [ '.bg-brand-500 {\n  background-color: #3b82f6;\n}\n' ] (succeeds)
Because tailwind-verifier.ts hardcodes '@import "tailwindcss";' without detecting or passing '@config "./tailwind.config.js";', valid theme colors defined in the project's own theme are falsely refused.
